# LuxUI 에디터 프레임워크

`Editor/LuxUI`를 Qt 6 기반의 별도 라이브러리 `LuxUI::LuxUI`로 분리했다. 에디터의 앱·뷰포트·애니메이션·도구·테스트는 `<LuxUI/...>`를 사용한다. Qt 헤더를 직접 include하는 위치는 LuxUI 백엔드로 제한한다. 엔진 SDK에는 LuxUI나 Qt 의존성이 들어가지 않는다.

`Widgets.hpp`는 기존 위젯 코드의 호환 바인딩과 실제 Application/MainWindow 기반을 제공한다. Qt의 소유권·이벤트 루프·메타 객체 규칙을 따르는 **Qt 기반 API**이며, 다른 백엔드로 바꿔도 모든 코드가 그대로 동작하는 불투명 GUI API를 표방하지 않는다. 새 에디터 기능은 공통 명령·메시지·측정 서비스를 사용한다.

## 공통 서비스

- `MessageStore`: 제한된 크기의 로그 저장소. 작업 스레드는 메시지를 넣고 UI 스레드는 순번 기준 스냅샷을 읽는다.
- `CommandRegistry`: 고유 ID·표시 이름·실행 함수·활성 조건을 갖는 제작 명령. 메뉴와 콘솔에서 같은 명령을 실행한다.
- `FrameHistory`: 최근 측정 기록·평균·95백분위 CPU 시간을 관리한다.
- `ConsolePanel`: 수준·문자열 필터, 로그 저장, 명령 입력을 제공한다.
- `ProfilerPanel`: 업데이트·뷰포트 CPU 시간, GPU 시간, Draw Call과 추적 GPU 할당량, 그래프와 CSV 내보내기를 제공한다.
- `AssetList`: 에셋의 실제 파일 URL을 내보내는 드래그 브라우저다. 프로젝트 파일 이름과 이미지 썸네일은 기존 Content Browser의 필터·폴더 탐색과 결합한다.

GPU 시간이 지원되지 않으면 측정 불가로 표시한다. CPU 업데이트/뷰포트 측정은 프로세스 전체 CPU 점유율이나 프레임 전체 FPS가 아니다. 할당량도 GPU 드라이버의 전체 VRAM 사용량과 다르다.

## 플레이와 입력

Scene View와 Game View를 별도 탭으로 제공한다. Scene View의 2D/3D 편집 카메라·격자·선택·기즈모는 저작 씬을 보여준다. Game View는 실행 전에도 저작 씬의 Primary Camera 화면을 미리 보여 주며 편집용 격자나 기즈모를 표시하지 않는다. 플레이 중에는 독립 실행 씬으로 전환하고 종료하면 저작 씬 미리보기로 돌아온다.

F5로 현재 씬을 즉시 플레이하고 F6 일시정지, F7 한 프레임, Shift+F5 종료를 사용한다. 시작할 때 씬을 직렬화해 독립 실행 씬을 만들고 Jolt·C# 업데이트는 이 복제본에만 적용한다. 종료하면 실행 씬을 폐기하며 저작 씬과 Undo 이력은 유지한다. 플레이 도중 Scene View에서 수행한 저작 편집도 종료 시 덮어쓰지 않는다.

플레이용 C# 어셈블리는 도구 메뉴에서 선택한다. 기본 경로는 프로젝트 `Scripts/GameScripts.dll`이다. 플레이 중 포커스를 가진 Game View의 키보드·마우스 입력만 엔진 외부 입력 브리지로 전달하고, 포커스 상실·탭 숨김·일시정지·종료 시 해제한다. Scene View의 이동 키가 게임 조작으로 전달되지 않는다. 별도 프로세스로 실행하는 기능은 기존 플레이어 실행 경로를 사용한다.

3D 뷰포트는 우클릭+WASD 이동, Q/E 상하, Shift 가속을 지원한다. Alt+우클릭은 궤도 회전을 유지한다. F로 선택에 초점을 맞추고, 이동·회전·크기 기즈모와 로컬/월드 좌표·다중 선택·Undo/Redo를 함께 사용한다. Position은 격자에 반올림하지 않는다.

우클릭 회전은 오른쪽 포인터 이동에 오른쪽 보기, 아래쪽 이동에 아래쪽 보기를 대응한다. Qt 이벤트의 논리 좌표에는 이미 시스템 포인터 속도와 가속이 반영돼 있으므로 별도 감도 배율이나 DPI 배율을 중복 적용하지 않는다. 뷰포트 크기와 FOV로 회전량을 환산한다. 운영체제에는 공통적인 3D 카메라 감도 값이 없으므로 OS의 내부 설정 숫자를 직접 복사하는 방식은 아니다.

카메라 생성 메뉴에서 2D 직교·3D 원근 카메라 엔티티를 추가한다. 첫 카메라는 기본 게임 카메라가 되며, Details에서 다른 카메라를 기본으로 선택하면 이전 카메라의 기본 설정을 해제한다. 카메라 생성과 속성 변경은 Undo/Redo에 포함한다. Details에서 투영·시야각·직교 크기·3D near/far clip을 편집하며 저장한 씬과 별도 플레이어에도 같은 값을 적용한다. 현재 Scene View를 카메라에 맞추거나 선택 카메라 시점으로 편집 뷰를 이동할 수 있다. 2D 편집 뷰는 중심과 크기를 맞추고, 카메라 Z 회전이 적용된 실제 화면은 Game View에서 확인한다. 정지 상태의 Game View는 씬을 그리기만 하며 물리·스크립트를 진행하거나 게임 입력을 받지 않는다.

## 커스텀 도구

네이티브 확장은 `EditorWindow::RegisterTool(LuxUI::Command)`로 에디터 명령을 등록한다. Qt 헤더를 include할 필요 없이 ID·이름·콜백·활성 조건을 제공한다. 엔티티 변경은 `ExecuteRecordedEdit`를 사용해 Undo/Redo에 포함한다.

프로젝트 JSON 제작 도구는 명시적으로 불러온다. 셸 명령을 자동 실행하거나 프로젝트를 열었다는 이유로 외부 프로그램을 실행하지 않는다. 현재 지원 동작은 동적 3D 상자 묶음 생성이다.

```json
{
  "version": 1,
  "tools": [
    {
      "id": "physics-row",
      "title": "물리 상자 8개 배치",
      "action": "create_boxes",
      "count": 8,
      "spacing": 2.0
    }
  ]
}
```

콘솔의 `help`/`tools`로 명령을 보고 `play`, `pause`, `step`, `stop`, `frame`, `profiler` 등을 실행한다. C# 게임 스크립트 실행과 직렬화 필드 편집은 지원하며, C#으로 에디터 패널 자체를 작성하는 별도 확장 ABI는 아직 제공하지 않는다.

## 카메라 조작과 포인터 캡처

Scene View는 RMB 자유 회전·WASD/QE 이동·Shift 가속, MMB 화면 이동, Alt+LMB 궤도 회전(Alt+RMB 호환), 휠 돌리를 지원한다. 상단 이동 속도 필드와 RMB+휠로 속도를 바꾸고 F/Home으로 선택 항목·전체 장면에 초점을 맞춘다. 카메라 생성 후에는 이동 도구와 해당 카메라 초점을 자동으로 선택한다. W/E/R 기즈모는 오브젝트의 위치·회전·크기를 편집하며 카메라는 방향·시야 프러스텀과 표시 거리를 함께 시각화한다.

`LuxUI::PointerCapture`가 연속 회전을 위한 포인터 수명을 소유한다. X11·Windows·macOS에서는 지원되는 커서 재중앙화를 사용한다. Linux의 Qt 6.10 이상에서는 선택적 QtWaylandClient·wayland-client·wayland-protocols·wayland-scanner를 찾으면 공개 Qt API와 relative-pointer/pointer-constraints 프로토콜을 사용한다. Qt가 소유한 포인터 리스너와 private ABI는 변경하지 않는다. 프로토콜 코드는 설치된 XML에서 로컬로 생성하며 다운로드하지 않는다. `LUX_UI_ENABLE_WAYLAND_CAPTURE=OFF`로 이 백엔드를 제외할 수 있다.

상대 입력은 시스템 가속이 적용된 논리 좌표를 사용하고 DPI 배율을 다시 곱하지 않는다. 캡처 해제·포커스 상실·창 파괴 시 잠금과 커서를 복원한다. Qt·컴포지터가 잠금을 지원하지 않으면 Limited 상태와 실제 제한을 알리며 무제한 회전이 동작한다고 표시하지 않는다.
