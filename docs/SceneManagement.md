# 씬 관리

`docs/EditorRoadmap.md`의 3번 항목을 구현했다. 에디터는 `LuxEngine::Scene`과 `SceneManager`를 프레임워크로 사용하고, 문서·작업 이력·Qt 화면은 `LuxEditor` 모듈에서 관리한다.

## 편집 흐름

- 새 씬과 파일 열기는 별도 문서 탭을 만든다. 같은 파일을 다시 열면 기존 탭을 선택한다. 탭마다 선택 항목, 저장 경로, 수정 여부를 유지하고 `*`로 미저장 상태를 표시한다. 닫기·씬 삭제·프로젝트 전환에서는 미저장 작업을 확인한다.
- 파일 메뉴에서 저장·다른 이름으로 저장, 씬 메뉴에서 모든 씬 저장·복제·파일 삭제를 실행한다. 프로젝트의 시작 씬은 현재 씬으로 지정할 수 있다. 시작 씬 파일의 삭제는 차단한다.
- Outliner에서 검색, 다중 선택, 부모·자식 드래그, 그룹화·그룹 해제·부모 연결 해제를 사용한다. 부모를 바꿀 때 월드 변환을 유지한다. 복사·붙여넣기와 다른 씬으로 이동은 자손과 컴포넌트도 처리한다. ID 충돌은 새 ID로 바꾼다.
- 씬 전환 효과는 씬 메뉴에서 켜거나 끈다. `Ctrl+Tab`과 `Ctrl+Shift+Tab`으로 문서를 전환한다. 미리보기 중 문서를 바꾸거나 복제하면 편집 상태를 먼저 복원한다.
- Undo/Redo는 명령을 실행한 문서를 다시 활성화한다. 씬 간 이동은 양쪽 문서를 한 번에 되돌린다. 참여 문서를 닫으면 그 문서를 참조하는 명령을 폐기한다. 일상적인 선택·편집 메시지는 콘솔에 쌓지 않고 실패와 필요한 진단만 표시한다.

## 참조와 로딩

씬 메뉴의 중첩·인스턴스, 상속, Additive 로드는 독립적인 참조 루트 아래에 원본 엔티티를 가져온다. 같은 원본도 여러 번 배치할 수 있다. 참조 루트의 속성에는 경로·방식·로드 상태와 원본 열기·경로 변경을 표시한다. 참조 갱신·선택 참조 다시 로드·언로드·경로 변경은 작업 이력으로 되돌릴 수 있다.

상속 갱신은 **엔티티 단위 Override**를 사용한다. 로컬에서 수정한 엔티티와 명시적으로 삭제한 원본 엔티티를 보존하고, 수정하지 않은 엔티티의 변경 및 원본의 새 엔티티를 반영한다. 씬 설정은 수정하지 않은 필드를 상속한다. 속성별 Override 목록을 제공하는 프리팹 편집기는 별도 기능이다.

일반 열기, 비동기 열기, 프리로드를 지원한다. 비동기 작업은 CPU에서 파일을 읽고 검증하며 Qt 위젯과 GPU에 접근하지 않는다. 진행 중 문서를 전환하거나 같은 파일을 먼저 열어 수정해도 늦게 도착한 결과가 기존 문서를 덮어쓰지 않는다. 프리로드 캐시 비우기는 열린 문서를 닫지 않는다. 참조 언로드는 현재 자손의 직렬화 가능한 편집 상태를 보관하고 다시 로드할 때 복원한다. 언로드된 영역의 애니메이션 재생 시간이나 물리 접촉 상태를 저장하는 실행 스냅샷은 아니다.

스트리밍은 선택한 참조 루트에 **월드 XY 중심, 로드 반경, 언로드 반경**을 지정한다. 에디터의 2D 카메라 중심 또는 실행 중 플레이어의 월드 XY 위치를 관측점으로 사용한다. 플레이어가 없으면 기본 화면 중심을 사용한다. 관측점이 범위에 진입하면 비동기로 가져오고, 더 큰 언로드 반경을 벗어나면 해제한다. 로드 반경 0은 스트리밍을 끈다. 카메라 방향이나 3D 시야 절두체를 사용하는 스트리밍은 아니다. 상태가 바뀌지 않은 틱에는 전체 씬을 복제하지 않는다. 스트리밍 적용 중 기존 물리 접촉과 애니메이션 재생 위치를 유지한다.

## 씬 설정과 파일

씬 설정에서 배경색, 노출, 중력 Override, 2D·3D 중력, 물리 고정 시간 간격과 서브스텝을 편집한다. 배경색·노출은 편집 화면과 실행 렌더링에 적용하고, 물리는 씬별 설정을 사용한다. 중력 Override를 끄면 기존 전역 중력을 따른다. 설정 창을 변경 없이 확인해도 원래 부동소수점 값을 보존한다.

씬 파일은 v3 형식으로 저장하고 v1·v2도 읽는다. 계층·씬 설정·참조 원본과 기준 상태·언로드 상태·ID 대응 관계를 함께 저장한다. 잘못된 숫자, 부모 누락, 계층 및 파일 참조 순환, 잘못된 ID 대응을 검증한 뒤 적용한다. 저장은 임시 파일을 거쳐 교체하며 실패 시 기존 파일과 문서를 보존한다. 참조 경로는 저장 파일 기준 상대 경로로 기록하므로 다른 이름으로 저장하거나 프로젝트를 옮겨도 원본의 의미를 유지한다.

자동 저장은 탭별 프로젝트 소유권과 원래 씬 경로를 유지한다. 세션 복원은 비활성 탭의 더 최신 자동 저장도 확인한다. 참조 파일이 없어 합성 로드가 실패하면 경고와 함께 저장된 편집 데이터를 열어 경로를 복구할 수 있다. 프로젝트 빌드·내보내기 전에는 중첩 참조와 보관된 상태까지 읽기 전용으로 검사하고, 프로젝트 밖 참조와 순환을 거부한다.

## 프리팹

씬 메뉴의 **프리팹**에서 선택한 오브젝트와 자손을 `.luxprefab` 파일로 저장한다. 원본 오브젝트는 현재 씬에 남고, 저장한 파일은 Content Browser의 장면 필터에서 찾을 수 있다. 파일을 두 번 누르거나 **프리팹 배치**를 사용하면 독립적인 인스턴스가 만들어진다. 프리팹 파일은 씬 JSON 형식을 사용하지만 최상위 오브젝트 하나만 허용한다.

배치한 인스턴스에는 별도의 그룹 루트와 원본 연결이 생긴다. 같은 원본을 여러 번 배치할 수 있으며 각 인스턴스는 서로 다른 엔티티 ID를 사용한다. C#의 엔티티 참조 필드도 해당 인스턴스의 ID로 변환한다. 선택한 계층을 내보낼 때 계층 밖의 엔티티 참조는 비운다.

- **선택 프리팹 갱신**은 수정하지 않은 원본 엔티티의 변경을 반영하고 로컬에서 수정하거나 삭제한 엔티티를 유지한다. 비교 단위는 엔티티 전체다. 한 속성만 수정해도 해당 엔티티의 다른 속성은 원본 갱신에서 보호된다.
- **로컬 변경 되돌리기**는 원본의 현재 계층과 속성을 복원하고 로컬 추가 오브젝트를 제거한다. 살아 있는 원본 대응 엔티티의 ID와 인스턴스 그룹의 배치는 유지한다. 이미 삭제한 원본 엔티티를 복원할 때는 새 ID를 부여한다.
- **연결 해제**는 배치된 오브젝트와 자손을 유지하면서 해당 인스턴스의 원본 연결을 제거한다. 안쪽에 별도로 연결된 프리팹은 독립적인 연결을 유지한다.
- 배치·갱신·되돌리기·연결 해제는 씬의 Undo/Redo에 연결한다. 프리팹 파일 저장은 프로젝트 에셋 작업이므로 씬 Undo로 파일을 삭제하지 않는다.

원본을 변경하려면 원본을 만들었던 오브젝트 계층을 수정한 뒤 같은 파일로 저장하고 필요한 인스턴스를 갱신한다. 연결된 인스턴스를 자신의 원본 파일 위에 저장하는 동작은 소스 엔티티 식별자를 보호하기 위해 거부한다. 인스턴스를 새 이름으로 저장해 독립 프리팹을 만드는 것은 지원한다. 전용 원본 편집 모드, 변경 속성별 Override 목록, 인스턴스 변경을 원본에 적용하는 명령, 프리팹 Variant는 현재 지원 범위에 포함하지 않는다.

`LuxEngine::PrefabLibrary`는 엔진 공개 API로 저장·배치·갱신·되돌리기·연결 해제를 제공한다. `Instantiate()`의 반환 ID는 씬 참조를 소유하는 인스턴스 컨테이너다. 원본 최상위 오브젝트는 그 컨테이너의 자식이며, 원본 엔티티와 실제 엔티티의 대응은 `SceneReferenceComponent::entityMap`에서 조회한다. 인스턴스 전체 이동·갱신·되돌리기·연결 해제에는 컨테이너 ID를 사용한다. 기존 `SceneReferenceComponent`의 경로·기준 상태·ID 매핑을 재사용하므로 구형 씬의 읽기를 유지한다. 원본 파일이 손상됐거나 잘못된 계층이면 열린 씬의 변경 없이 실패한다. 원본과 인스턴스 경로는 씬 저장 시 상대 경로로 기록하며 프로젝트 이동 후에도 다시 해석한다. 프로젝트 밖의 프리팹 참조는 게임 빌드 검증에서 거부한다. 생성 게임과 설치 SDK의 콘텐츠 복사는 `.luxprefab` 파일을 포함한다.

`Engine_prefab_library`는 파일 저장 실패 보존, 원본 ID 안정성, 인스턴스별 C# 참조, 갱신·로컬 삭제·되돌리기·연결 해제, 잘못된 입력의 원자성과 프로젝트 재배치를 검사한다. `Editor_prefab_ui`는 실제 Content Browser의 배치, 메뉴 명령, Undo/Redo와 프로젝트 경계 검증을 검사한다.

## 범위와 제한

- Transform은 위치·회전·크기(TRS)다. 비균일 크기와 회전 조합으로 생긴 전단을 새 부모 아래에서 정확히 표현할 수 없으면 월드 변환 유지 재부모화를 거부한다. 기존 부모 아래에서 위치만 이동할 때는 로컬 회전·크기를 보존한다. 렌더링은 전체 월드 행렬을 사용한다.
- 작업 이력은 최대 128개 명령, 스냅샷 데이터 합계 256 MiB 예산을 사용한다. 예산을 넘으면 오래된 기록을 해제한다. 한 명령 자체가 예산보다 크면 그 명령 하나는 유지한다. 저장하지 않은 문서 자체가 이 제한으로 삭제되지는 않는다.
- 로딩 캐시는 원본·프리로드 합계 32개 항목, 직렬화 데이터 64 MiB를 한도로 사용 순서에 따라 비운다. 단일 씬 파일은 64 MiB, 한 번의 참조 로드 데이터는 128 MiB, 합성 씬은 100,000개 엔티티, 참조는 128개, 중첩 깊이는 16으로 제한한다.
- 기본 엔진 컴포넌트를 직렬화·복사한다. 직렬화 방법이 등록되지 않은 사용자 컴포넌트가 있으면 데이터를 버리는 대신 관련 복사·저장·상태 교체를 거부한다.

```sh
ctest --test-dir build -R 'Engine_scene|Editor_scene|Editor_recovery_history' --output-on-failure
```

`LuxEditorSceneUiTests`는 기본 실행에 화면 캡처를 요구하지 않는다. `LUX_EDITOR_SCENE_CAPTURE`를 PNG의 절대 경로로 지정하면 별도 예제 프로젝트로 실제 에디터 화면을 캡처한다. 실제 디스플레이에서 `LUX_EDITOR_SCENE_CAPTURE_GPU=1`도 지정하면 엔진 GPU 렌더링을 사용한다.

실제 GPU 렌더링으로 캡처하려면 정상 디스플레이 세션에서 `LUX_EDITOR_SCENE_CAPTURE_GPU=1`도 지정한다.
